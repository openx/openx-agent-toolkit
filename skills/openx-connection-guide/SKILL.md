OpenX MCP: tools over the OpenX external API for deals, packages, audiences and forecasting.

Skills are step-by-step playbooks served by this server. Before any multi-step job, call getSkill with the matching name and follow it; listSkills lists them. If your client loads tools on demand and a skill or the user names a tool that is not in your session, search the connector's tools for it by exact name: every tool a skill names is reachable through this connection.

Before any create, update, activate or archive, tell the user exactly what will change and wait for a yes. The request itself is not that yes, even when it names exactly what to change; skip the question only when the user has said to go ahead without checking.

Instances and accounts. A write -- create*, update*, activate*, archive* -- lands on exactly one instance: the instance_uid you pass, or the instance your credential signed in to when you omit it. It is never inferred from the account, so settle both before the first write. For OpenXSelect work, call listAccountsForProduct and pass the chosen row's id as account_id and its instance_uid as instance_uid on every create. For anything else, call getUserInstances: with one instance, omit instance_uid; with several, ask the user which to work in (show names, not uids) and pass that uid unchanged on every call. searchOptionsByPath with path "account" and that instance_uid lists the accounts you can use there. Omitting account_id creates in your own account only on the instance you signed in to; on any other instance it can land in that instance's root account, so pass account_id whenever you pass instance_uid. Reads are looser: a list or search without instance_uid spans every instance you can see, while a get by id without instance_uid looks only in the instance you signed in to and, for an object that lives elsewhere, fails with a 'Wrong instance' error naming the instance_uid to pass. Every deal, package, signal, pixel and curated deal buyer discount carries its instance_uid (searchOptionsByPath results in extra); pass it on every call about that object. With a single instance none of this applies.

Deals that share targeting share one package: create it once with createPackage and pass its id as package_id to each createDeal, since an inline package repeats the whole targeting, block lists included, in every call.

An error that starts with 'Wrong instance' means the object lives on another instance: find its instance_uid with searchOptionsByPath (which searches every instance you can see) and retry the same call once with it. An error that starts with 'Not retryable' is final: the account lacks a permission or a feature, so do not retry or vary the call; tell the user what the message says to request. One exception: a permission error on a write, when you hold more than one instance, is how a missing or wrong instance_uid is reported. Retry that once with the object's own instance named before telling the user to contact support. Available skills:
- openx-audience-build: Build, size, price and activate an OpenXSelect audience through the OpenX MCP tools - turn a plain-language description of who a campaign should reach into segments, a compiled definition, a reach estimate, a price, a saved audience and an export you can check on. Use when asked to find, build, size, estimate, price, create, edit or activate an audience in OpenXSelect, to turn a persona or RFP audience brief into a targetable audience, to answer "how many people are X in Y", or to check whether an audience has finished publishing. For the deal that will target the audience (publishers, domains, apps, geo of the ad request), use openx-deal-creation instead.
- openx-deal-creation: Create a new OpenX XP deal (with its targeting package) through the OpenX MCP tools, including resolving format, device, channel and geo targeting ids, demand partners, the format/channel/device compatibility and targeting-blocking rules (CTV vs viewability/VTR, Banner/Native vs TV devices, App-only/Web-only blocks), and avoiding the backend pitfalls that make createDeal fail or leave orphaned packages. Use whenever someone asks to create, set up, build, or make a new deal in OpenX, even casually ("create me a new deal", "set up a test deal for a Zurich mobile banner", "make a deal for TTD"), or when someone asks which formats, devices, channels or quality thresholds (viewability, VTR) can be combined in a deal, what deal type or pricing (floor vs fixed price) a new deal gets, or when a deal creation attempt has failed and needs recovery.
- openx-deal-troubleshooter: Troubleshoot OpenX deal performance end to end — health checks, funnel bottlenecks, bid-loss reasons, hourly spikes/drops, daily trends, dimension breakdowns, targeting inspection and audit-trail changes. Use whenever someone gives a deal code (OX-...) or deal name and asks why it's underdelivering, where the funnel leaks, why bids are losing (overall or by publisher, DSP, domain or bundle), what changed, how a deal is pacing, which targeting setting is throttling it, or wants a general "deal health check" — even if they don't name a specific tool. Also use to resolve an OX-... deal code to its numeric id when other OpenX tools need one.
