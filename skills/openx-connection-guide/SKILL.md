OpenX MCP: tools over the OpenX external API for orders, line items, creatives, deals, packages, audiences, delivery metrics and forecasting.

Skills are step-by-step playbooks served by this server. Before any multi-step job, call getSkill with the matching name and follow it; listSkills lists them. If your client loads tools on demand and a skill or the user names a tool that is not in your session, search the connector's tools for it by exact name: every tool a skill names is reachable through this connection.

Before any create, update, activate, pause, archive, add or remove, tell the user exactly what will change and wait for a yes. The request itself is not that yes, even when it names exactly what to change; skip the question only when the user has said to go ahead without checking.

Instances and accounts. A write -- create*, update*, activate*, pause*, archive*, add*/remove* -- lands on exactly one instance: the instance_uid you pass, or the instance your credential signed in to when you omit it. It is never inferred from the account, so settle both before the first write. For OpenXSelect or OpenXDirect work, call listAccountsForProduct and pass the chosen row's id as account_id and its instance_uid as instance_uid on every create. For anything else, call getUserInstances: with one instance, omit instance_uid; with several, ask the user which to work in (show names, not uids) and pass that uid unchanged on every call. searchOptionsByPath with path "account" and that instance_uid lists the accounts you can use there. Omitting account_id creates in your own account only on the instance you signed in to; on any other instance it can land in that instance's root account, so pass account_id whenever you pass instance_uid. Reads are looser: a list or search without instance_uid spans every instance you can see, while a get by id without instance_uid looks only in the instance you signed in to and, for an object that lives elsewhere, fails with a 'Wrong instance' error naming the instance_uid to pass. Every deal, package, order, line item, creative, signal, pixel and curated deal buyer discount carries its instance_uid (searchOptionsByPath results in extra); pass it on every call about that object. With a single instance none of this applies.

Deals that share targeting share one package: create it once with createPackage and pass its id as package_id to each createDeal, since an inline package repeats the whole targeting, block lists included, in every call.

An error that starts with 'Wrong instance' means the object lives on another instance: find its instance_uid with searchOptionsByPath (which searches every instance you can see) and retry the same call once with it. An error that starts with 'Not retryable' is final: the account lacks a permission or a feature, so do not retry or vary the call; tell the user what the message says to request. One exception: a permission error on a write, when you hold more than one instance, is how a missing or wrong instance_uid is reported. Retry that once with the object's own instance named before telling the user to contact support. Available skills:
- openx-audience-build: Build, size, price and activate an OpenXSelect audience through the OpenX MCP tools - turn a plain-language description of who a campaign should reach into segments, a compiled definition, a reach estimate, a price, a saved audience and an export you can check on. Use when asked to find, build, size, estimate, price, create, edit or activate an audience in OpenXSelect, to turn a persona or RFP audience brief into a targetable audience, to answer "how many people are X in Y", or to check whether an audience has finished publishing. For the deal or line item that will target the audience (publishers, domains, apps, geo of the ad request), use openx-deal-creation or openx-campaign-launch instead.
- openx-budget-reallocate: Move budget between the line items of one OpenXDirect order through the OpenX MCP tools. Reads every line item's budget, spend to date and pace, proposes a split that keeps the order's total (decreases first, never below what a line item has spent, only into line items whose forecast can absorb it), gets a yes, applies it one line item at a time, re-reads each one and reports per line item. Use when asked to move money or budget between line items, shift budget from underspending to capped line items, rebalance or reallocate an order's budget, or give one line item more at another's expense.
- openx-bulk-change: Pause, resume or change many OpenXDirect line items at once through the OpenX MCP tools, one object at a time, safely. Scopes the set to one named order or a filter the user confirmed, shows every affected line item with its current spend before the first write, applies the change line item by line item, re-reads each one and reports per object what succeeded and what did not. Use when asked to pause everything under an order or campaign, hold or stop spend, resume or unpause a campaign, raise or lower the budget, bid or CPM on several line items, or make the same change across a set of line items.
- openx-campaign-launch: Launch an OpenXDirect campaign end to end through the OpenX MCP tools - create the order, creative and line item, attach the creative, forecast, then activate - with the id, unit and lookup rules each step needs. Use when asked to create, set up, launch or test a campaign, order, line item or creative in OpenXDirect, or to run the campaign flow through the OpenX MCP.
- openx-deal-creation: Create a new OpenX XP deal (with its targeting package) through the OpenX MCP tools, including resolving format, device, channel and geo targeting ids, demand partners, the format/channel/device compatibility and targeting-blocking rules (CTV vs viewability/VTR, Banner/Native vs TV devices, App-only/Web-only blocks), and avoiding the backend pitfalls that make createDeal fail or leave orphaned packages. Use whenever someone asks to create, set up, build, or make a new deal in OpenX, even casually ("create me a new deal", "set up a test deal for a Zurich mobile banner", "make a deal for TTD"), or when someone asks which formats, devices, channels or quality thresholds (viewability, VTR) can be combined in a deal, what deal type or pricing (floor vs fixed price) a new deal gets, or when a deal creation attempt has failed and needs recovery.
- openx-deal-troubleshooter: Troubleshoot OpenX deal performance end to end — health checks, funnel bottlenecks, bid-loss reasons, hourly spikes/drops, daily trends, dimension breakdowns, targeting inspection and audit-trail changes. Use whenever someone gives a deal code (OX-...) or deal name and asks why it's underdelivering, where the funnel leaks, why bids are losing (overall or by publisher, DSP, domain or bundle), what changed, how a deal is pacing, which targeting setting is throttling it, or wants a general "deal health check" — even if they don't name a specific tool. Also use to resolve an OX-... deal code to its numeric id when other OpenX tools need one. If the deal belongs to OpenXDirect, hand off to the "Diagnose a Line Item" skill (openx-delivery-troubleshoot) instead.
- openx-delivery-troubleshoot: Diagnose why an OpenXDirect line item or campaign is not delivering, through the OpenX MCP. It only reads while it diagnoses, and applies a fix only when the user asks. Reads the delivery counters first (requests, bids, fills, impressions) to see where the funnel breaks, then walks a fixed checklist from the cheapest configuration causes to forecast and sibling comparison, and reports the first failing check and the fix. Use when asked why a line item, order or campaign is not delivering, not spending, not bidding, stalled, or shows Active but has no impressions.
- openx-pacing-review: Review delivery pacing across the line items of an OpenXDirect order or account through the read tools of the OpenX MCP. Scopes the set, pulls delivery and pacing for all of it in bulk, and produces one table with a flag per line item (on pace, behind, well behind, ahead, not started) plus the order's own pace, with the unit caveats that make the numbers honest. Use when asked which line items are underspending, behind or ahead of pace, how a campaign or order is pacing this week, or for a pacing or delivery check across an order.
